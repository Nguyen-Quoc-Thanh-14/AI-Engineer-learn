## E04.01 — MRO và super()

> **Trạng thái biên soạn:** BẢN THẢO CHUYÊN BIỆT CÓ NỘI DUNG; ĐÃ CHẠY ĐẠT — Python 3.13.5. **Chưa phản biện sư phạm độc lập.**  
> **Giai đoạn:** GD3 · **Chương:** E04 — Kế thừa nâng cao · **Python đích:** CPython 3.15.2.

### 1. Điều kiện tiên quyết và chuẩn đầu ra

**Tiên quyết:** B, C. Trước bài này, cần nắm khái niệm đã dùng trong chương.

Sau bài học, bạn phải làm được: (i) giải thích **MRO và super()** không cần nhìn mã; (ii) dự đoán đầu ra và diễn giải từng bước; (iii) sửa/áp dụng ví dụ; (iv) nêu được một giới hạn, một lỗi biên và phương pháp kiểm chứng.

### 2. Khái niệm và vì sao cần học

MRO (method resolution order) là thứ tự tìm method khi class có kế thừa; CPython/Python dùng C3 linearization. `super()` gọi implementation tiếp theo trong MRO, không nhất thiết là “class cha trực tiếp”.

**Ngữ cảnh thực tế:** Trong chương **Kế thừa nâng cao**, nội dung này giúp quyết định cách thiết kế/kiểm tra giải pháp khi dự án có đầu vào hoặc yêu cầu thay đổi. Không chọn kỹ thuật chỉ vì cú pháp ngắn; cần xem tính đúng, độ rõ ràng và hành vi lỗi.

### 3. Cơ chế — mô hình thực thi

Kiểm tra `C.__mro__` để hiểu chuỗi gọi trong multiple inheritance; cooperative methods nên dùng chữ ký tương thích.

**Quy trình phân tích:** Xác định dữ liệu đầu vào và điều kiện hợp lệ → theo dõi thứ tự đánh giá và thay đổi trạng thái → kiểm tra kết quả đầu ra và exception → đối chiếu với contract, không chỉ với một lần chạy.

### 4. Ví dụ độc lập, có assertion

```python
class Base:
    def who(self): return ['Base']
class Left(Base):
    def who(self): return ['Left'] + super().who()
class Right(Base):
    def who(self): return ['Right'] + super().who()
class Child(Left, Right): pass
assert Child().who() == ['Left', 'Right', 'Base']
assert Child.__mro__[1:3] == (Left, Right)
```

**Trạng thái thực thi:** ĐÃ CHẠY ĐẠT — Python 3.13.5. Mã nguồn độc lập tại [`E04.01_demo.py`](MA_MAU/E04.01_demo.py). `assert` trong ví dụ dùng làm phép thử minh họa, không thay thế test suite đầy đủ.

**Cách tự học với ví dụ:** Che phần assertion cuối, dự đoán kết quả theo cơ chế phần 3; sau đó chạy và so sánh. Thử thay một input hợp lệ và một input vi phạm contract.

### 5. Trường hợp biên và lỗi thường gặp

Dùng tên class cha cố định trong method có thể phá chuỗi cooperative super trong diamond inheritance.

**Bảng kiểm tự thực hiện:**

| Tình huống | Cần kiểm tra |
|---|---|
| Đầu vào thường | Hành vi đúng hợp đồng; không phát sinh side effect không dự kiến |
| Đầu vào rỗng/giá trị biên | Cách trả kết quả, lỗi và fallback có được mô tả? |
| Đầu vào sai/ngoài miền | Có từ chối rõ ràng, không gây mất dữ liệu hay lộ thông tin? |

**Bài A — Phân tích:** Tự giải thích kết quả của đoạn mã ở phần 4, nêu rõ ít nhất hai bước thực thi và kiểm tra trường hợp biên.

**Bài B — Ứng dụng:** Đổi thứ tự parent class và dự đoán chuỗi gọi dựa trên `__mro__`.

**Bài C — Phản biện:** Thử một giải pháp thay thế, so sánh về tính đúng, chi phí bảo trì/hiệu năng và độ an toàn trong tình huống có input không tin cậy.

## E04.02 — ABC, abstract methods và Protocol

> **Trạng thái biên soạn:** BẢN THẢO CHUYÊN BIỆT CÓ NỘI DUNG; ĐÃ CHẠY ĐẠT — Python 3.13.5. **Chưa phản biện sư phạm độc lập.**

### 2. Khái niệm và vì sao cần học

ABC áp đặt interface bằng abstract methods khi khởi tạo, trong khi `typing.Protocol` mô tả structural subtyping cho static type checker.

**Ngữ cảnh thực tế:** Trong chương **Kế thừa nâng cao**, nội dung này giúp quyết định cách thiết kế/kiểm tra giải pháp khi dự án có đầu vào hoặc yêu cầu thay đổi. Không chọn kỹ thuật chỉ vì cú pháp ngắn; cần xem tính đúng, độ rõ ràng và hành vi lỗi.

### 3. Cơ chế — mô hình thực thi

`ABC` kiểm tra abstract method ở runtime; `Protocol` thông thường phục vụ kiểm tra tĩnh; `@runtime_checkable` chỉ hỗ trợ kiểm tra cấu trúc hạn chế.

**Quy trình phân tích:** Xác định dữ liệu đầu vào và điều kiện hợp lệ → theo dõi thứ tự đánh giá và thay đổi trạng thái → kiểm tra kết quả đầu ra và exception → đối chiếu với contract, không chỉ với một lần chạy.

### 4. Ví dụ độc lập, có assertion

```python
from abc import ABC, abstractmethod
class Storage(ABC):
    @abstractmethod
    def get(self, key): ...
class Memory(Storage):
    def __init__(self): self.data = {'a': 3}
    def get(self, key): return self.data[key]
assert Memory().get('a') == 3
try: Storage()
except TypeError: pass
else: raise AssertionError()
```

### 2. Khái niệm và vì sao cần học

Mixin là class bổ sung hành vi nhỏ cho class khác thông qua multiple inheritance; nó không nhất thiết biểu diễn quan hệ “là một”.

### 3. Cơ chế — mô hình thực thi

Mixin hoạt động qua method lookup và nên tránh giữ trạng thái khởi tạo phức tạp; dùng `super()` đúng khi hợp tác với các class khác.
