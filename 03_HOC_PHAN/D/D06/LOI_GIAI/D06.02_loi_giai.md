# Lời giải bài tập vận dụng — D06.02 (v2.7)

**Đề bài B (từ bản gốc v2.6):** Viết overload parse cho hai kiểu input và thử checker static trên trường hợp không khớp.

**Trạng thái kiểm định:** Mã dưới đây đã chạy dưới tiến trình Python 3.13.5 độc lập, không có lỗi ngoài dự kiến. Đây là kiểm thử minh họa trên dữ liệu xác định, không phải bằng chứng tương thích 3.15.2 hoặc mọi hệ điều hành/thư viện.

## Thiết kế và giả định

Lời giải triển khai trường hợp sử dụng xác định theo yêu cầu bài B. Các `assert` minh họa tối thiểu ca chuẩn, ca biên hoặc từ chối đầu vào sai khi thích hợp; bài sử dụng công cụ/thư viện ngoài vẫn phải được kiểm thử trên môi trường đích.

## Mã hoàn chỉnh

```python
from typing import overload
@overload
def parse(value: int) -> int: ...
@overload
def parse(value: str) -> int: ...
def parse(value: int | str) -> int:
    if isinstance(value, bool): raise TypeError('bool không thuộc contract')
    if not isinstance(value, (int, str)): raise TypeError('chỉ int hoặc str')
    if isinstance(value, str) and not value.strip(): raise ValueError('chuỗi rỗng')
    return int(value)
assert parse(12)==12
assert parse(' 07 ')==7
try: parse([])
except TypeError: pass
else: raise AssertionError('runtime check phải từ chối')
# Việc kiểm overload với mypy/pyright KHÔNG được xác nhận bởi các assert runtime này.
print('PASS D06.02')
```

- Không suy ra tính đúng với mọi đầu vào từ các `assert` này; bổ sung property-based tests, kiểm thử đầu vào lỗi và tests hồi quy khi triển khai dự án.
- Để đáp ứng phần **thử static checker** của Bài B, `tests/issue9_d0602_overload_checker.py` dùng AST trích chính hai chữ ký `@overload` và implementation từ file B, tạo cả fixture hợp lệ (`int`/`str`) lẫn fixture bất hợp lệ (`list`). Workflow Issue #9 buộc mypy và pyright chấp nhận trường hợp đúng, từ chối trường hợp sai. Chỉ ghi PASS khi có log của đúng SHA; kiểm thử runtime không thay thế kiểm thử static.
- Tránh coi kiểm thử minh họa là xác nhận chất lượng/hiệu năng/bảo mật khi chạy thực tế.
