# F04.01 — Lời giải Bài B: ContextVar request ID và kiểm soát secret log

**Đề bài từ tài liệu học:** Gắn context request ID vào LogRecord và kiểm log không chứa secret.

## Hợp đồng

- Một request được gắn ID trong `contextvars.ContextVar`; filter chuyển ID đã kiểm tra định dạng lên `LogRecord.request_id`.
- Dữ liệu request ID không tin cậy: chỉ cho phép chữ ASCII/số/`_`/`-`, tối đa 64 ký tự; ID không hợp lệ thành `invalid-id`, tránh tạo nhiều dòng log hoặc đưa nội dung không kiểm soát vào log.
- Thông điệp mẫu có `token=...` / `api_key=...` được che trước khi ghi log. Sau khi request kết thúc, reset token ContextVar để không lẫn ID qua request khác.

## Mã chạy riêng và cách thử

[Mở F04.01_bai_B_solution.py](../../../../31_HOAN_THIEN_LOI_GIAI_V28/F04.01_bai_B_solution.py). Có hàm `render_log(message, rid)` trả chuỗi log để so sánh trong test.

```python
from pathlib import Path
import runpy

source = Path("31_HOAN_THIEN_LOI_GIAI_V28/F04.01_bai_B_solution.py")
render_log = runpy.run_path(str(source))["render_log"]
out = render_log("done token=SYNTHETIC", "req-42")
assert out.startswith("req-42 ")
assert "SYNTHETIC" not in out
assert "token=[REDACTED]" in out
```

Kiểm thử thêm: request ID có newline, ID quá dài, message không phải chuỗi, ContextVar reset. Chạy trên CPython 3.15.2:

```bash
python 31_HOAN_THIEN_LOI_GIAI_V28/F04.01_bai_B_solution.py
python -m unittest discover -s tests -p 'test_issue9_security_contracts.py' -v
```

## Giới hạn và phản biện

Đây là ví dụ minh họa LogRecord + ContextVar, **không phải hệ thống log an toàn toàn diện**. Filter không che mọi loại secret trong stack trace, JSON, structured logging hay handlers không dùng filter. Không được ghi secret vào log ngay từ đầu; log pipeline thật cần quy trình scrub, thử nghiệm tích hợp và chính sách retention/truy cập phù hợp. Chỉ công nhận các ca cụ thể đã chạy đạt; **chưa có phản biện chuyên gia độc lập**.
