# F03.03 — Lời giải vận dụng độc lập (v2.8)

## Lời giải thiết kế — Bài B (v2.8)

**Đề bài:** Viết quy trình build → inspect dist → test install → upload thử TestPyPI.

1. Configure `pyproject.toml` with `[build-system]`, `[project]`, classifiers and `requires-python`.
2. Create clean environment: `python -m pip install build twine`.
3. Run `python -m build`; expect one wheel and one `.tar.gz` sdist in `dist/`.
4. Check `python -m twine check dist/*`, unpack artifacts, inspect metadata and exclude secret files.
5. In fresh environment install the built wheel, then run project tests and the console entry point.
6. Upload **only to TestPyPI** with restricted token and `python -m twine upload --repository testpypi dist/*`; test installation using the TestPyPI index and an explicit PyPI fallback when necessary for dependencies. Production PyPI requires separate approval. Never commit token or expose it in CI log.

**Trạng thái:** Lời giải dạng thiết kế/quy trình. Không đánh giá là chương trình đã chạy.
