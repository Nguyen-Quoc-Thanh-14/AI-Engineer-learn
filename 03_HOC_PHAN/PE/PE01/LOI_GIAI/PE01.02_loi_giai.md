# PE01.02 — Lời giải vận dụng độc lập (v2.8)

## Lời giải thiết kế — Bài B (v2.8)

**Đề bài:** Thiết kế ETL và ELT cho cùng dữ liệu orders, so trust boundary.

**ETL:** validate and normalize `orders` from API in Python (reject negative qty, unify UTC and decimal currency), then load curated records to analytics DB. **ELT:** load raw immutable orders with checksums into a restricted staging bucket/table, then transform in the warehouse using version-controlled SQL. Contracts shared: unique order ID, required source timestamp, nonnegative quantity, idempotent upsert key, bounded freshness and failure alert. **Trust boundary:** raw PII in staging requires access control even before transformation. Verify that replaying same batch does not duplicate orders; inject bad rows and compare rejection counts.

**Trạng thái:** Lời giải dạng thiết kế/quy trình. Không đánh giá là chương trình đã chạy.
