# M05.01 — Đáp án Bài B: SQLAlchemy ORM và ràng buộc UNIQUE

**Đề bài:** Thiết kế hai bảng ORM User/Order và kiểm chứng unique constraint bằng database thật.

## Phương pháp chính

Dùng **SQLAlchemy 2.x Declarative ORM** với hai class `User`, `Order`, ánh xạ quan hệ `User.orders` ↔ `Order.user` và `ForeignKey("users.id")`. Trên SQLite in-memory, bật `PRAGMA foreign_keys=ON`. Column `email` có ràng buộc `UNIQUE` tại database, không chỉ kiểm tra bằng Python.

[Mã nguồn chạy riêng M05.01_bai_B_solution.py](../../../../31_HOAN_THIEN_LOI_GIAI_V28/M05.01_bai_B_solution.py). Hàm `run_demo()` tạo schema qua `Base.metadata.create_all` (chỉ dùng cho lab), ghi một User + Order hợp lệ, thử ghi email trùng và **xác nhận SQLite trả `IntegrityError`**, rồi kiểm chứng số dòng và quan hệ ORM.

```bash
python -m pip install sqlalchemy
python 31_HOAN_THIEN_LOI_GIAI_V28/M05.01_bai_B_solution.py
python -m unittest discover -s tests -p 'test_issue9_orm_contracts.py' -v
```

**Ca biên:** email trùng phải bị database từ chối; transaction lỗi phải được rollback; số bản ghi không đổi; FK chỉ có hiệu lực khi SQLite bật `foreign_keys`. Sử dụng tài khoản/địa chỉ giả trong bộ test.

**Giới hạn:** `metadata.create_all` **không phải migration production**. Nếu cần nâng cấp schema thực tế, dùng Alembic/chiến lược migration có version, backup và thử nghiệm rollback. Lời giải trước dùng `sqlite3` thuần và **chưa chứng minh việc tạo models ORM**. Đã hiệu đính theo đề; chờ CI trên SHA mới và phản biện độc lập, không tự chứng nhận.
