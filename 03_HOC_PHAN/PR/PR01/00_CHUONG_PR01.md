# PR01.01 — FFI/ctypes/cffi và ranh giới dữ liệu

> **Trạng thái:** ĐÃ BIÊN SOẠN BẢN THẢO CHUYÊN BIỆT; VÍ DỤ VÀ LỜI GIẢI CHẠY ĐẠT PYTHON 3.13.5.
> **Giai đoạn:** GD6 · **Chương:** PR01 — Python với native code · **Đích:** CPython 3.15.2.

## 1. Chuẩn đầu ra có thể kiểm chứng

1. Tự giải thích khái niệm **FFI/ctypes/cffi và ranh giới dữ liệu**, nêu một trường hợp nên và không nên áp dụng.
2. Dự đoán trạng thái/kết quả ví dụ trước khi chạy và giải thích từng bước.
3. Viết một lời giải độc lập, xử lý ít nhất ba trường hợp (bình thường, biên, sai đầu vào).
4. Chỉ ra giả định, giới hạn và đối chiếu kết quả bằng kiểm thử.

**Tiên quyết:** F, J, K, L.

## 2. Khái niệm — Bản chất

Foreign Function Interface (FFI) cho Python gọi hàm/native library. Crossing boundary yêu cầu thống nhất ABI, kiểu dữ liệu, ownership và error handling; lỗi sai có thể gây crash process thay vì exception an toàn. `ctypes` thuộc stdlib, `cffi` là thư viện ngoài; không nên gọi thư viện hệ thống chưa biết nguồn.

## 3. Nguyên lý và cơ chế từng bước

Ví dụ không nạp thư viện C bên ngoài: dùng `ctypes.Structure` để minh họa layout trường C-compatible và kích thước. Layout phụ thuộc platform và alignment; ví dụ không suy ra byte size cụ thể.

## 4. Ví dụ tối thiểu có thể chạy

```python
import ctypes
class Point(ctypes.Structure):
    _fields_=[('x',ctypes.c_int),('y',ctypes.c_int)]
p=Point(2,3)
assert p.x==2 and p.y==3
assert ctypes.sizeof(Point)>=2*ctypes.sizeof(ctypes.c_int)
print(p.x,p.y)
```

**Kết quả kiểm thử cục bộ:** pass trên Python 3.13.5.

```text
2 3
```

**Thực hành:** chạy file `07_MA_VI_DU/PR01.01_vi_du.py` từ thư mục gốc giáo trình rồi sửa một tham số để dự đoán sự khác biệt.

## 5. Trường hợp biên, lỗi thường gặp và hướng debug

- **Ngộ nhận:** Không truyền con trỏ vào vùng nhớ đã giải phóng; không đoán argtypes/restype khi gọi hàm C.
- **Trường hợp biên:** Alignment, packing và ABI thay đổi giữa platform/compiler.
- **Debug có phương pháp:** xác định hợp đồng → tái hiện lỗi bằng đầu vào tối thiểu → đọc traceback/kiểm tra trạng thái → sửa → thêm regression test.

## 11. Bài chuyên sâu bổ sung v2.5 — kiểm định bằng chương trình thực thi

> **Kết quả:** Đã chạy thành công lời giải độc lập trên Python 3.13.5 tại thời điểm xuất bản v2.5. **Chưa kiểm định trực tiếp trên CPython 3.15.2; chưa qua phản biện sư phạm độc lập.**

### Nguyên lý cần nắm

FFI chuyển quyền kiểm soát bộ nhớ qua ranh giới Python–native; ctypes không tự đảm bảo rằng độ dài nguồn/đích được kiểm tra khi gọi hàm như memmove.

### Cách suy luận và thiết kế lời giải

Tạo buffer C có kích thước cố định, kiểm tra payload là bytes và không dài hơn capacity trước khi copy. Đây là ví dụ minh họa ranh giới bộ nhớ; dùng API Python thuần nếu không có nhu cầu FFI thực tế.

### Phản ví dụ và ngộ nhận cần tránh

Không cấp phát buffer size n rồi sao chép n+1 bytes; đây là dạng lỗi native memory corruption nguy hiểm. Đừng tự nhận ctypes đảm bảo memory safety.

### Lộ trình tự kiểm tra

1. Đọc yêu cầu bài tập ở trên, tự viết lời giải **trước khi mở đáp án**.
2. Dự đoán đầu ra các trường hợp bình thường, biên và không hợp lệ; nói rõ từng precondition, hậu điều kiện.
3. Chạy mã độc lập [`PR01.01_bai_tap_da_giai_v25.py`](MA_MAU/PR01.01_bai_tap_da_giai_v25.py) để đối chiếu.
4. Kiểm tra lời giải chi tiết: [`PR01.01_loi_giai.md`](LOI_GIAI/PR01.01_loi_giai.md).
5. **Bài mở rộng:** Chuyển ví dụ sang cffi hoặc extension có kiểm tra bounds, phân tích ownership và lifetime của pointer; không giữ pointer tới vùng đã giải phóng.

**Nguồn kỹ thuật chính thức:** https://docs.python.org/3.15/library/ctypes.html. Tài liệu được dùng để đối chiếu API/cơ chế, không phải nguồn sao chép nguyên văn bài này.

## 2. Khái niệm và vì sao cần học

FFI call có overhead; native code chỉ có lợi khi một call thực hiện đủ tính toán hoặc tránh copying lớn.

**Ngữ cảnh thực tế:** Trong chương **Python với native code**, nội dung này giúp quyết định cách thiết kế/kiểm tra giải pháp khi dự án có đầu vào hoặc yêu cầu thay đổi. Không chọn kỹ thuật chỉ vì cú pháp ngắn; cần xem tính đúng, độ rõ ràng và hành vi lỗi.

## 3. Cơ chế — mô hình thực thi

Đo call-per-element so vector batch; report crossing overhead và throughput.

**Quy trình phân tích:** Xác định dữ liệu đầu vào và điều kiện hợp lệ → theo dõi thứ tự đánh giá và thay đổi trạng thái → kiểm tra kết quả đầu ra và exception → đối chiếu với contract, không chỉ với một lần chạy.

## 4. Ví dụ độc lập, có assertion

```python
import timeit
samples=timeit.repeat('abs(-2)',repeat=2,number=1000)
assert min(samples)>=0
```

**Trạng thái thực thi:** ĐÃ CHẠY ĐẠT — Python 3.13.5. Mã nguồn độc lập tại [`PR01.04_demo.py`](MA_MAU/PR01.04_demo.py). `assert` trong ví dụ dùng làm phép thử minh họa, không thay thế test suite đầy đủ.

**Cách tự học với ví dụ:** Che phần assertion cuối, dự đoán kết quả theo cơ chế phần 3; sau đó chạy và so sánh. Thử thay một input hợp lệ và một input vi phạm contract.

## 5. Trường hợp biên và lỗi thường gặp

Không benchmark chỉ native inner loop mà bỏ chi phí chuyển dữ liệu.

**Bảng kiểm tự thực hiện:**

| Tình huống | Cần kiểm tra |
|---|---|
| Đầu vào thường | Hành vi đúng hợp đồng; không phát sinh side effect không dự kiến |
| Đầu vào rỗng/giá trị biên | Cách trả kết quả, lỗi và fallback có được mô tả? |
| Đầu vào sai/ngoài miền | Có từ chối rõ ràng, không gây mất dữ liệu hay lộ thông tin? |
